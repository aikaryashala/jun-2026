The assignment should require students to build the **same CLI application twice**:

1. **C language**
2. **Python language**

The application is a **Mini HTML Parser that converts HTML content into an in-memory DOM tree**.

The students must use:

- **OpenCode** (`opencode.ai`) as their AI coding agent
- **Entire** (`entire.io`) to capture and preserve development context, decisions, and reasoning
- **Git/GitHub** for version control

The purpose is not merely to build an HTML parser. The assignment should teach students how software development changes when an AI coding agent is part of the development process.

# 3. Problem Statement

Given an HTML file such as:

```html
<html>
  <body>
    <h1>Hello</h1>
    <p>Welcome to AI Karyashala</p>
  </body>
</html>
```

the application must:

1. Read the HTML file.
2. Parse the HTML.
3. Construct an in-memory DOM tree.
4. Traverse the DOM tree.
5. Display the DOM tree in a format similar to the Linux `tree` command.

The output should look like:

```text
.
└── html
    └── body
        ├── h1
        │   └── "Hello"
        └── p
            └── "Welcome to AI Karyashala"
```

The important requirement is that the tree output must be generated by **traversing the in-memory DOM**, not by simply formatting the original HTML.

---

# 4. Scope of HTML

Do NOT require students to implement the complete HTML5 specification.

Define a small, clear subset of HTML.

The parser should initially support:

- Opening tags
- Closing tags
- Text nodes
- Nested elements
- Sibling elements
- Attributes
- Whitespace between elements

For example:

```html
<div>
  <h1>Hello</h1>
  <p class="intro">Welcome</p>
</div>
```

The parser should create a tree containing:

```text
div
├── h1
│   └── "Hello"
└── p [class="intro"]
    └── "Welcome"
```

Clearly state which HTML features are **out of scope**, such as:

- JavaScript
- CSS parsing
- HTML entities
- Browser rendering
- Complete HTML5 error recovery
- Comments, unless introduced as an optional extension
- DOCTYPE processing, unless introduced as an optional extension
- Script/style parsing

---

# 5. DOM Data Model

Require students to design an internal representation for the DOM.

At minimum, the DOM should represent:

### Element Node

- Tag name
- Attributes
- Children

### Text Node

- Text content

Explain that the exact implementation is left to the student.

For example, in C they may use structures, pointers, linked lists, or dynamic arrays.

In Python they may use classes, lists, dictionaries, or other suitable structures.

Do not prescribe the implementation unnecessarily.

---

# 6. Tree Output Requirement

This is an important part of the assignment.

The DOM must be displayed like the Unix `tree` command.

Use:

```text
├──
└──
│
```

appropriately.

Example:

```text
.
└── html
    └── body
        ├── h1
        │   └── "Hello"
        └── p
            └── "Welcome to AI Karyashala"
```

For attributes:

```text
.
└── html
    └── body
        ├── h1
        │   └── "Hello"
        └── p [class="intro", id="first"]
            └── "Welcome to AI Karyashala"
```

Text nodes must be displayed inside quotation marks.

The tree printer must be implemented by recursively traversing the DOM data structure.

# 7. CLI Interface

Define a simple command-line interface.

For example:

```text
domparser page.html
```

should display the DOM tree.

Also introduce useful options:

```text
domparser page.html --tree
domparser page.html --text
domparser page.html --tags p
domparser page.html --find-id first
domparser page.html --find-class intro
```

The exact command name can be chosen by the students, but the behavior must be documented.

---

# 8. Development Phases

Structure the assignment into incremental milestones.

## Phase 1 — Read HTML

- Read an HTML file.
- Display its contents.
- Understand the input.

## Phase 2 — Tokenization / Parsing

- Identify opening tags.
- Identify closing tags.
- Identify text.

## Phase 3 — Build DOM

- Create the DOM node representation.
- Build parent-child relationships.
- Support nested elements.

## Phase 4 — Tree Display

Traverse the DOM recursively and produce the `tree`-style output.

## Phase 5 — Attributes

Support attributes such as:

```html
<p class="intro" id="first">Hello</p>
```

## Phase 6 — Validation

Detect basic malformed HTML.

Examples:

```text
Unclosed tag: <p>
Unexpected closing tag: </div>
```

## Phase 7 — Queries

Add simple DOM queries:

```text
--find-tag p
--find-id first
--find-class intro
```

## Phase 8 — Testing and Refactoring

Create tests for:

- Simple elements
- Nested elements
- Multiple siblings
- Text nodes
- Attributes
- Empty elements
- Malformed HTML
- Deeply nested HTML
